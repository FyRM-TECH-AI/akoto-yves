## Commands

Package manager is **Bun** (`bun.lock`, `bunfig.toml`). If `bun` isn't on PATH, it's usually at `~/.bun/bin/bun.exe` on Windows; `npm`/`npx` also work (single package, no workspaces).

- Dev: `bun run dev` — Vite on http://localhost:8080
- Build: `bun run build` — client to `dist/client`, Nitro server to `.output/` (preset `node-server`)
- Run the built server: `bun run start` (`node .output/server/index.mjs`, respects `PORT`)
- Lint: `bun run lint` (`eslint .`) — `eslint-plugin-prettier/recommended` is appended globally, so lint also fails on formatting. `bun run format` = `prettier --write .` (`.prettierrc`: width 100, double quotes, semicolons, trailing commas).
- Typecheck: no script — `bunx tsc --noEmit`.
- Test: `bun run test` (`vitest run`), `bun run test:watch`; single file: `bunx vitest run src/test/app-routing.test.tsx`.

No CI workflows and no pre-commit hooks: nothing verifies a change unless you run lint / tsc / test yourself.

## Toolchain quirks

- `vite.config.ts` is a plain Vite config: MDX (`enforce: "pre"` so it beats Start's transforms), Tailwind, `tanstackStart({ server: { entry: "server" } })`, `nitro()`, React. Nitro's default preset is `node-server`; set `NITRO_PRESET` for other targets.
- `@/` → `src` is an explicit alias in `vite.config.ts` (mirrored in `vitest.config.ts`); `vite-tsconfig-paths` is intentionally not used.
- `src/routeTree.gen.ts` is generated by the router plugin: never edit by hand. `.prettierignore` lists it, but ESLint's ignores (`dist`, `.output`, `.vinxi`) do not, so `lint` still sees the generated file.
- `bunfig.toml` sets `minimumReleaseAge = 86400`: `bun add` skips versions published in the last 24h. Adding a package to `minimumReleaseAgeExcludes` bypasses that guard — confirm with the user first.
- `tsconfig.json` is stricter than default: `exactOptionalPropertyTypes`, `noUncheckedIndexedAccess`, `noPropertyAccessFromIndexSignature`, `noImplicitReturns`. Expect type errors that wouldn't appear in a stock React app.

## Architecture

- TanStack Start (framework mode) + Vite 8 + React 19 + TypeScript; TanStack Router file-based routes; Tailwind v4 via `@tailwindcss/vite`; shadcn/ui (`components.json`: new-york, slate, CSS vars, `@/` alias) in `src/components/ui`.
- Routes live in `src/routes` — read `src/routes/README.md` before adding one (no `src/pages/`, `app/layout.tsx`, etc.). `__root.tsx` is the only shell and must keep `<Outlet />`; each route exports `head()` with title/description/og meta.
- Router setup: `src/router.tsx` (`getRouter`, React Query in route context, scroll restoration). Nav items are hardcoded in `src/components/SiteShell.tsx`.
- Server: `tanstackStart.server.entry: "server"` → `src/server.ts` normalizes h3-swallowed SSR 500s (JSON `{"unhandled":true,"message":"HTTPError"}`) into the HTML error page; `src/lib/error-capture.ts` patches `console.error` to recover the real stack.
- `src/start.ts` exists only because defining it opts out of Start's auto-installed CSRF middleware — keep the explicit `createCsrfMiddleware` when editing it.
- `importProtection` in `vite.config.ts` errors on importing `server-only` or `**/server/**` files from client code.

## Styling

- `src/styles.css` uses `@import "tailwindcss" source(none)` + `@source "../src"`: Tailwind only scans `src`, so classes authored elsewhere are dropped.
- Site-specific utilities `display`, `meta`, `animate-marquee` and color tokens `blue`, `green`, `subtle`, `on-color` are declared there — prefer them over new arbitrary values.
- Light theme only in practice (a `dark` variant exists but no `.dark` class is ever applied).

## Content & assets

- Portfolio copy lives in `src/lib/profile.ts` (profile, education, certificates, experiences, projects); pages stay presentational.
- Blog posts: drop a `.mdx` file in `src/content/blog/` exporting `export const meta = { title, date, summary?, tags? }`. Slug = filename, ordering = `date` desc, discovery via `import.meta.glob` in `src/lib/posts.ts` (no backend). `src/mdx.d.ts` types only the default export, so `meta` is typed through `posts.ts`.
- Certificate images are plain files in `public/certs/` referenced as `/certs/certN.jpg` from `profile.ts`.

## Gotchas

- ESLint flat config only targets `**/*.{ts,tsx}` and ignores `dist`, `.output`, `.vinxi`. It bans importing `server-only` (Next-ism): rename to `*.server.ts` or use `@tanstack/react-start/server-only`.
- `react-refresh/only-export-components` warns on non-constant non-component exports; `@typescript-eslint/no-unused-vars` is off.
- Tests: vitest + jsdom, `globals: true`, setup at `src/test/setup.ts` (mocks `scrollTo`/`matchMedia`), include `src/**/*.{test,spec}.{ts,tsx}`. `app-routing.test.tsx` only calls `router.matchRoutes` — deliberately avoids loaders and rendering, which need a server/network and stylesheets jsdom never loads.
